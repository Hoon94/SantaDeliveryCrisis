# 산타의 작업실 탈출 (Santa's Delivery Crisis) 스펙 문서

- 상태: 초안 v0.1 (팀 리뷰 전)
- 마감: 2026-11-22
- 관련 문서: [확정 내역과 질의응답](../../docs/project-understanding.md) / [추가 구현 목록](../../docs/future-work.md) / [원본 기획 자료](../../docs/references/planning)
- 표기
  - **[가정]**: 문서를 쓰면서 제안했지만 팀이 아직 확정하지 않은 내용입니다.
  - **미정**: 제안 없이 팀의 결정을 기다리는 내용입니다.
  - Kiro는 `[가정]`과 미정 항목을 확정된 규칙처럼 구현하지 않고, 구현 전에 사용자에게 먼저 확인합니다. 모아서 확인하는 곳은 16장입니다.

## 1. 개요

iOS 개발 학습용 퀴즈 앱입니다. 산타의 빈 크리스마스 트리를 꾸미는 게임 형식으로 진행합니다.
사용자는 "작업"(카테고리)을 고르고 세션(한 판)을 풀어서 트리 장식을 얻습니다. 장식 12칸이 모두 차면 트리가 완성되고, 산타가 루돌프를 타고 선물을 주러 떠납니다.

**목표 사용자:** iOS와 개발에 관심 있는 사람. 쉽게 풀 수 있고, 게임식 보상으로 오래 쓰게 만드는 것이 목표입니다.

## 2. 범위

### 2-1. 1차 구현 범위
- 퀴즈 CRUD(만들기·보기·고치기·지우기). 텍스트, 이미지, 영상 문제
- 4지선다 단일 선택 문제
- 코드 실행을 줄별 애니메이션으로 보여 주는 문제(3~5개 유형)
- 반응형 출제("오늘의 출제"는 4개 작업을 섞어서 앱이 구성)와 작업 추천
- 작업, 난이도, 태그를 골라 출제 대상을 거르는 선택 출제
- 세션 진행, 이어서 풀기, 결과 요약(점수, 오답 노트, 추천 학습 자료)
- 트리 장식 보상, 트리 완성, 완성 기록 보관
- 주/월 성과 대시보드
- 설정(정답률 기준 등), 다크모드, iPhone(세로)과 iPad(가로·세로), 접근성

### 2-2. 범위 밖
- 1차에서 제외한 기능은 [future-work.md](../../docs/future-work.md)에 모두 있습니다.
- macOS, 다국어(한국어로 통일), 로그인, 서버 연동은 지원하지 않습니다.

## 5. 게임 규칙

1. 세션은 두 가지 방식으로 시작합니다. 사용자가 4개 작업 중 하나를 직접 고르거나(해금 조건 없음), 앱이 4개 작업을 섞어서 구성한 "오늘의 출제"로 시작합니다.
2. 앱은 사용자의 취약점과 선호도를 조합해 한 작업에 "추천" 배지를 붙입니다(7-3).
3. 난이도(쉬움/보통/어려움)와 문제 수(5/10/15)를 고르고 세션을 시작합니다. 작업을 직접 고른 경우에는 태그도 고를 수 있습니다.
4. 세션이 끝나면 정답률을 계산합니다.
   - 정답률이 **기준 이상**이면 장식을 받습니다. 기본 기준은 80%이고, 설정에서 50~100%(10% 단위)로 바꿀 수 있습니다.
   - 장식 수는 난이도로 정해집니다. 쉬움 1개, 보통 2개, 어려움 3개. 문제 수는 보상에 영향이 없습니다.
   - 기준 미만이면 장식을 받지 못하지만 벌칙은 없습니다.
5. 트리는 한 그루이고 4개 작업의 장식이 같은 트리에 쌓입니다. 장식은 12칸입니다.
6. 12칸이 모두 차면 트리가 완성됩니다. 산타가 출발하는 연출을 보여 주고, 완성한 트리는 보관함에 저장하며, 빈 트리를 새로 시작합니다. 퀴즈 기록, 통계, 설정은 유지됩니다.
7. 받을 장식이 남은 칸보다 많으면 남은 칸을 채워 트리를 완성하고, 초과분은 새로 시작하는 트리로 이월합니다. 예: 11칸이 찬 트리에서 3개를 받으면 1개로 완성하고 2개는 새 트리에 채웁니다.
8. 쉬운 세션을 반복해서 빨리 완성하는 것은 막지 않습니다.
9. 세션 중 앱을 종료하면 진행 상황이 저장되고, 다시 켜면 "이어서 풀기"로 계속합니다. 진행 중 세션은 동시에 1개만 허용합니다.

## 7. 기능 상세

### 7-1. 문제 풀이 (S4, S5)
- 보기 하나를 선택하고 **[확인]** 버튼을 눌러 채점합니다. 확인 전에는 선택을 바꿀 수 있습니다.
- 일반 문제: 확인 즉시 피드백을 표시합니다.
- 애니메이션 문제: 확인 후 애니메이션을 재생하고, 끝나면 정답 여부와 해설을 표시합니다. 건너뛰기와 다시 보기는 1차에 없습니다.
- 피드백
  - 정답: 초록색, ✓ 아이콘과 문구, 햅틱 `.success`, 효과음
  - 오답: 빨간색, ✕ 아이콘과 문구, 햅틱 `.error`, 보기 좌우 흔들림, 효과음
  - 색만으로 구분하지 않습니다.
- 답은 문제마다 저장됩니다(7-5 이어서 풀기).

### 7-2. 세션 결과 (S6)
- 보상 장식이 트리로 날아가는 연출은 이 화면에서 재생합니다. 문제별 연출에는 쓰지 않습니다.
- 오답이 있으면 오답 노트로 이동할 수 있고, 오답 문제의 학습 자료 링크를 "추천 학습 자료"로 모아서 보여 줍니다.
- 트리가 완성되면 완성 연출(산타 출발)을 이 화면에서 이어서 재생합니다.

### 7-3. 반응형 출제와 추천

세션은 두 가지 방식으로 시작합니다.

| 방식 | 시작 위치 | 카테고리 | 사용자가 고르는 것 |
| --- | --- | --- | --- |
| 오늘의 출제 | S1의 버튼 | 4개 작업을 섞어서 앱이 구성 | 난이도, 문제 수 |
| 작업 선택 | S2에서 작업을 고름 | 고른 작업 하나 | 난이도, 태그(선택), 문제 수 |

**작업 추천 (`TaskRecommender`)**: S2의 "추천" 배지에 씁니다.
- 입력: 최근 답 기록(최근 30일)
- 점수 = 취약도 70% + 선호도 30%
  - 취약도 = 1 - 해당 카테고리 정답률 (기록이 없으면 0.5)
  - 선호도 = 해당 카테고리 문제를 푼 수 / 전체 푼 문제 수
  - 카테고리는 답한 문제의 스냅샷(`QuestionSnapshot.category`) 기준입니다.
- 점수가 가장 높은 작업에 "추천" 배지를 붙입니다. 점수가 같으면 작업 순서(소원 접수, 선물 생산, 포장, 썰매 적재)에서 앞선 작업을 추천합니다. 기록이 전혀 없으면 첫 작업(소원 접수)을 추천합니다.

**문제 선택 (`QuestionSelector`)**
선택한 난이도의 문제 중에서 다음 비율로 고릅니다. 후보 범위는 오늘의 출제는 4개 작업 전체, 작업 선택은 고른 카테고리와 태그(고른 경우)입니다. 태그를 고르지 않으면 전체 태그가 대상이고, 여러 개를 고르면 그중 하나라도 가진 문제가 대상입니다. 아래 비율은 이 후보 안에서 같은 방식으로 적용합니다.

| 비율 | 오늘의 출제 | 작업 선택 |
| --- | --- | --- |
| 50% | 약한 문제: 최근 오답이거나 정답률이 낮은 문제 | 같음 |
| 30% | 선호 카테고리 문제: 사용자가 자주 푼 카테고리의 문제 **[가정]** | 선호 태그 문제: 사용자가 자주 푼 태그의 문제 |
| 20% | 오래 안 푼 문제 또는 한 번도 안 푼 문제 | 같음 |

- 범주별 문제 수는 비율대로 계산해 내림하고, 남는 자리는 약한 문제 범주부터 채웁니다. 5문제는 3·1·1, 10문제는 5·3·2, 15문제는 8·4·3입니다.
- 한 문제가 여러 범주에 해당하면 약한 문제 → 선호(카테고리 또는 태그) → 오래 안 푼 문제 순서로 먼저 배정하고, 한 번 뽑힌 문제는 다른 범주 후보에서 뺍니다. 중복 출제는 없습니다.
- 한 범주에서 후보가 모자라면 나머지 범주에서 같은 순서로 채웁니다.
- 세 범주를 모두 쓰고도 문제 수가 모자라면 같은 필터 안의 남은 후보에서 중복 없이 무작위로 채웁니다. 필터 전체의 후보 자체가 모자라면 `startSession`이 오류를 던집니다(S3는 `availableCount`로 미리 막습니다).
- "정답률이 낮은 문제"와 "오래 안 푼 문제"의 기준값, 범주 안에서의 선택과 동률 처리는 작업 2 담당자가 정하고 문서화 주석에 적습니다.
- 기록이 없는 새 사용자는 모든 문제를 "한 번도 안 푼 문제"로 보고 무작위로 고릅니다.
- 정해진 문제 수에서 순서는 무작위로 섞습니다.
- 작업을 직접 고른 세션은 후보가 모두 같은 카테고리라서 "선호 카테고리" 대신 "선호 태그"를 씁니다.

### 7-4. 애니메이션 문제 (코드 트레이스)
참고 구현: [rabbit-quiz-v3.html](../../docs/references/planning/rabbit-quiz-v3.html)

- 문제는 코드 조각, 보기, 장면(캐릭터와 배경), 실행 순서로 구성됩니다.
- 확인 후 코드를 한 줄씩 하이라이트하면서 캐릭터가 그 줄을 실행하고, 말풍선에 조건 결과와 변수 값을 표시합니다.
- 공통 컴포넌트(코드 줄 하이라이트, 변수 표시, 말풍선)는 재사용하고, 장면은 유형별로 만듭니다. 1차 유형은 3~5개(예: 조건문, 반복문, 옵셔널, guard)입니다.
- 캐릭터와 배경은 이미지 에셋을 SwiftUI 애니메이션으로 움직입니다. 코드로 도형을 그리지 않습니다.
- 애니메이션 문제는 앱 내장 시드 데이터로만 제공합니다. 문제 관리(S10)에서는 목록 조회만 가능하고, 수정·삭제 버튼은 다른 시드 문제와 같이 화면에 표시하되 비활성화합니다(7-7).
- 접근성
  - 모션 줄이기가 켜져 있으면 캐릭터 이동을 생략하고 코드 줄 하이라이트와 텍스트 설명만 보여 줍니다.
  - VoiceOver에는 "1번째 줄: apples는 3으로 설정됩니다"처럼 줄별 실행 설명을 텍스트로 제공합니다.
- `animationID`로 장면을 찾지 못하면(`scene(for:)`가 `nil`) 애니메이션 없이 정답 판정과 해설만 보여 줍니다. 앱이 죽지 않아야 합니다.
- 코드 토큰 탭 설명은 1차에 없고 해설 텍스트로 대신합니다.

### 7-5. 이어서 풀기
- 문제 하나에 답하고 [확인]을 누를 때마다 세션 상태를 SwiftData에 저장합니다.
- 앱을 시작할 때 `inProgress` 상태 세션이 있으면 S1에 "이어서 풀기"를 보여 줍니다.
- 복원 위치는 저장된 답의 수(`answers.count`)번째 문제입니다. `currentIndex`는 답을 저장하는 같은 저장에서 `answers.count`와 같은 값으로 갱신하고, 둘이 다르면 `answers.count`를 따릅니다. 이미 답이 저장된 문제는 다시 채점하지 않습니다.
- 모든 문제의 답이 저장된 상태에서 종료됐다면, 복원할 때 문제 화면 없이 결과 계산(`finish`)부터 진행합니다.
- 피드백이나 애니메이션을 보던 도중에 종료됐다면, 다시 재생하지 않고 다음 문제로 이동합니다. 놓친 해설은 결과 화면의 오답 노트에서 볼 수 있습니다.
- 소요 시간(`elapsedSeconds`)은 퀴즈 화면이 떠 있고 앱이 활성 상태인 동안만 누적합니다. 답을 저장할 때와 앱이 백그라운드로 갈 때 저장하고, 이어 풀 때는 저장된 값에서 이어서 더합니다. 마지막 문제의 피드백·애니메이션을 보는 시간도 포함하며, `finish`가 마지막 누적값을 저장한 뒤 확정합니다. 앱이 강제 종료되면 마지막 저장 이후의 시간은 빠질 수 있습니다.
- 진행 중 세션이 있는데 사용자가 새 세션을 시작하려고 하면 "이어서 풀기"와 "새로 시작(기존 세션 버림)" 중 고르게 하고, 새로 시작을 고르면 확인 대화상자를 한 번 보여 준 뒤 기존 세션을 `abandoned`로 바꿉니다.

### 7-6. 기록 대시보드 (S9)
- 주/월 전환 세그먼트
- 표시: 퀴즈 시도 횟수, 평균 점수, 풀이 문제 수 막대 차트, 평균 점수 추이 선 차트, 취약 카테고리 (정답률 낮은 순)
- 완성한 트리 기록: 완성 횟수와 최근 완성일. 상세는 보관함(S8)에서 봅니다.
- 집계 기준
  - 시도 횟수: 끝낸(`completed`) 세션 수. 중간에 그만둔(`abandoned`) 세션과 진행 중 세션은 제외
  - 평균 점수: 세션별 정답률(%)의 평균을 반올림한 정수
  - 기간: 주간은 월요일 시작(월요일로 고정), 월간은 그 달 1일 시작. 세션이 끝난 시각(`finishedAt`) 기준
  - 소요 시간: `elapsedSeconds`

### 7-7. 문제 관리 (S10, S11)
- 목록 검색, 카테고리/난이도 필터, 스와이프 삭제
- 편집 항목: 문제 텍스트, 이미지(사진 보관함에서 선택), 영상(사진 보관함에서 선택), 보기 4개, 정답, 해설, 힌트, 학습 자료(제목과 URL), 카테고리, 난이도, 태그
- 선택한 이미지와 영상은 앱 내부 폴더에 복사해서 저장합니다. 용량 제한은 두지 않습니다.
- 사용자 문제를 삭제하면 새 출제 대상과 오답 노트에서 빠지고, 그 문제의 이미지·영상 파일은 진행 중 세션이 쓰지 않을 때 지웁니다(8장 규칙). 진행 중 세션은 세션에 복사된 내용(8장)을 쓰므로 문제를 고치거나 지워도 이어 풀 수 있습니다.
- 시드 문제(`isSeed == true`)의 수정과 삭제 버튼은 화면에 표시하되 **비활성화**합니다. UI 확인용이며 동작은 1차에서 연결하지 않습니다. 사용자가 직접 만든 문제만 수정·삭제할 수 있습니다.
- 시드 문제 행에는 "기본 문제는 수정할 수 없어요" 같은 안내를 보여 줍니다.

### 7-8. 설정 (S12)

| 키 (@AppStorage) | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `hasLaunchedBefore` | Bool | false | 첫 실행 여부 (시드 주입과 온보딩 판단) |
| `passThresholdPercent` | Int | 80 | 보상 받는 정답률 기준 (50~100, 10 단위) |
| `soundEnabled` | Bool | true | 효과음 |
| `hapticsEnabled` | Bool | true | 진동 |

- 테마는 시스템 설정(라이트/다크)을 따릅니다. 앱 안에 테마 선택 설정은 없습니다.
- 글자 크기는 시스템 설정(Dynamic Type)을 따르고 앱 안에 별도 글꼴 크기 설정은 두지 않습니다. 과제의 "사용자 설정에 따라 폰트 크기 업데이트" 요구는 시스템 설정을 따르는 것으로 충족한다고 해석하며, 이 해석은 README에 설명합니다.

### 7-9. 문제 수 선택 활성화 조건
- 문제 수 선택지(5, 10, 15)는 후보 문제 수가 선택지 이상일 때만 활성화합니다. 조건은 `사용 가능한 문제 수 >= 선택지`입니다. 후보는 작업 선택 세션이면 선택한 작업·난이도·태그에 해당하는 문제, 오늘의 출제면 선택한 난이도의 4개 작업 전체 문제입니다. 태그를 바꾸면 즉시 다시 계산합니다.
- 1차에는 구간(작업 × 난이도)당 시드가 5문제입니다. 그래서 작업 선택 세션은 **5문제만 활성화**되고, 오늘의 출제는 난이도당 후보가 20문제(5×4작업)라서 5·10·15가 모두 활성화됩니다. 실제 활성화는 항상 `availableCount` 결과를 따릅니다.
- 문제가 추가되면(시드를 늘리거나 사용자가 만들면) 코드를 바꾸지 않아도 선택지가 자동으로 활성화됩니다.

## 8. 데이터 모델 (SwiftData)

팀원이 가장 먼저 합의해야 하는 부분입니다. 모델 파일은 작업 0(15장)에서 한 번에 만들고, 이후 변경은 PR 설명에 이유를 적습니다.

```swift
enum QuizCategory: String, Codable, CaseIterable {
    case aiUsage, swiftSyntax, hig, swiftUIPractice
}

enum Difficulty: String, Codable, CaseIterable {
    case easy, normal, hard
    /// 세션 성공 시 지급하는 장식 수 (쉬움 1, 보통 2, 어려움 3)
    var rewardDecorations: Int { /* 1, 2, 3 */ }
}

enum QuestionKind: String, Codable { case standard, animation }

@Model final class Question {
    @Attribute(.unique) var id: UUID
    var kind: QuestionKind
    var text: String
    var codeSnippet: String?          // 코드 문제의 코드
    var imageFileName: String?        // 앱 내부 폴더 상의 파일명
    var videoFileName: String?
    var choices: [String]             // 항상 4개
    var correctIndex: Int             // 0...3
    var explanation: String
    var hint: String?
    var resourceTitle: String?        // 추천 학습 자료
    var resourceURL: String?
    var category: QuizCategory
    var difficulty: Difficulty
    var tags: [String]
    var animationID: String?          // kind == .animation 일 때만 사용
    var isSeed: Bool
    var createdAt: Date
}

enum SessionStatus: String, Codable { case inProgress, completed, abandoned }

/// 세션 시작 시점의 문제 내용 복사본.
/// 원본 문제를 나중에 고치거나 지워도 진행 중 세션과 풀 당시의 문제 내용이 바뀌지 않게 한다.
/// 이미지·영상 파일은 복사하지 않고 파일명만 가진다(파일 보존 규칙은 아래 규칙 참고).
struct QuestionSnapshot: Codable {
    let questionID: UUID              // 통계 계산용 원본 id
    let category: QuizCategory        // 카테고리별 통계용 (혼합 세션에서도 문제별 카테고리를 알 수 있음)
    let kind: QuestionKind
    let tags: [String]                // 선호 태그 계산용 (원본이 바뀌거나 지워져도 풀 당시 태그를 알 수 있음)
    let animationID: String?
    let text: String
    let codeSnippet: String?
    let imageFileName: String?
    let videoFileName: String?
    let hint: String?
    let choices: [String]
    let correctIndex: Int
    let explanation: String
    let resourceTitle: String?
    let resourceURL: String?
}

@Model final class QuizSession {
    @Attribute(.unique) var id: UUID
    var category: QuizCategory?       // nil이면 오늘의 출제(4개 작업 혼합)
    var difficulty: Difficulty
    var questionIDs: [UUID]           // 출제 순서 고정
    var questionSnapshots: [QuestionSnapshot]  // questionIDs와 같은 순서의 문제 복사본
    var currentIndex: Int
    var status: SessionStatus
    var passThresholdPercent: Int     // 시작 시점의 기준값을 저장
    var startedAt: Date
    var finishedAt: Date?
    var elapsedSeconds: TimeInterval  // 퀴즈 화면이 떠 있던 시간의 누적 (앱이 꺼져 있던 시간 제외)
    var earnedDecorations: Int        // 완료 시 확정
    var carriedOverDecorations: Int   // 완료 시 확정. 새 트리로 이월된 장식 수
    var treeCompleted: Bool           // 완료 시 확정. 이 세션으로 트리가 완성되었는가
    @Relationship(deleteRule: .cascade) var answers: [SessionAnswer]
}

@Model final class SessionAnswer {
    var questionID: UUID
    var selectedIndex: Int
    var isCorrect: Bool
    var answeredAt: Date
}

@Model final class TreeRecord {
    @Attribute(.unique) var id: UUID
    var startedAt: Date
    var completedAt: Date?            // nil이면 현재 꾸미는 중인 트리
    var decorationCount: Int          // 0...12 (이월된 장식 포함)
}
```

규칙
- 현재 트리는 `completedAt == nil`인 `TreeRecord` 한 개입니다. 앱 첫 실행 때 생성합니다.
- 문제별 정답률, 마지막 풀이 시각은 `SessionAnswer`에서 계산하고 별도 통계 모델은 두지 않습니다. 중복 저장으로 값이 어긋나는 것을 막기 위해서입니다.
- 정답률 기준은 세션을 시작할 때의 값을 세션에 저장합니다. 도중에 설정을 바꿔도 이번 세션은 영향받지 않습니다.
- 세션을 시작할 때 출제 문제를 `questionSnapshots`에 복사합니다. 세션 진행, 결과, 오답 노트의 문제 내용은 원본 `Question`을 읽지 않고 이 복사본으로 그립니다.
- 미디어 파일은 불변으로 다룹니다. 문제의 이미지·영상을 바꾸면 기존 파일을 덮어쓰지 않고 새 파일명으로 저장합니다.
- **진행 중(`inProgress`) 세션이 스냅샷으로 참조하는 미디어 파일은 문제를 삭제하거나 미디어를 교체해도 지우지 않습니다.** 다음 중 어느 것도 참조하지 않는 파일만 삭제합니다: ① 어떤 `Question` ② 진행 중 세션의 스냅샷 ③ 원본 `Question`이 아직 남아 있는 문제의 끝난 세션 스냅샷(오답 노트에 풀 당시 내용으로 보이기 때문입니다). 원본 문제를 삭제하면 ③은 보존 대상에서 빠집니다. 정리는 문제 삭제, 미디어 교체, 세션 종료 직후와 앱 시작 때 수행합니다.
- 사용자가 문제를 삭제하면 그 문제는 오답 노트에서도 함께 사라집니다. 오답 노트는 원본 문제가 남아 있는 문제만 보여 주고, 세션의 점수와 정답률 같은 이미 확정된 기록은 바뀌지 않습니다. 문제를 수정한 경우에는 풀 당시의 내용(스냅샷)을 보여 줍니다. 진행 중 세션은 문제를 삭제해도 스냅샷으로 이어 풀 수 있습니다.
- 답(`SessionAnswer`)은 배열 순서가 아니라 `questionID`로 찾습니다. 한 세션에서 같은 `questionID`의 답은 하나만 존재합니다.
- 카테고리별 정답률(작업 추천, 작업별 정답률, 취약 카테고리)은 답한 문제의 스냅샷 `category`로 계산하고, 문제별 정답률은 `questionID`로 계산합니다. 문제를 수정해도 같은 `questionID`의 기존 풀이 기록과 통계는 그대로 유지합니다.
- 세션 완료 시 확정되는 값(`earnedDecorations`, `carriedOverDecorations`, `treeCompleted`)은 결과 화면을 다시 열 때 재계산하지 않고 그대로 읽습니다.
- 모델의 옵셔널 필드는 모두 안전하게 처리합니다(11장).

### 8-1. 시드 데이터
- 앱 번들의 JSON 파일(`Seed/questions.json`)을 첫 실행 때 SwiftData에 넣습니다. 같은 `id`가 이미 있으면 건너뜁니다.
- JSON 필드는 `Question` 모델 필드와 이름을 같게 맞춥니다. 이미지와 영상은 번들 에셋 파일명을 씁니다.
- 분량: 작업 4개 × 난이도 3개 × 구간당 최소 5문제 = **60문제 이상**
- 문제 작성은 팀원이 나눠서 하고, 한 구간의 형식이 통일되도록 작성 가이드(해설 길이, 보기 개수, 태그 규칙)를 `docs/question-guide.md`에 정합니다. **[가정]**

## 9. 모듈 인터페이스

각자 이 이름과 시그니처로 만들면 합칠 때 어긋나지 않습니다. 구현 안의 세부는 자유입니다.

```swift
/// 작업(카테고리) 추천
protocol TaskRecommending {
    func recommendedCategory(sessions: [QuizSession]) -> QuizCategory   // S2 추천 배지용
}

/// 세션용 문제 선택 (7-3 비율)
protocol QuestionSelecting {
    func select(
        category: QuizCategory?,    // nil이면 4개 작업 전체에서 고르는 오늘의 출제
        difficulty: Difficulty,
        tags: Set<String>,          // 비어 있으면 전체 태그. 여러 개면 하나라도 가진 문제. 오늘의 출제는 비움
        count: Int,
        questions: [Question],
        history: [QuizSession]      // 답(정오답, 시각)과 풀 당시 스냅샷(카테고리, 태그)을 함께 읽음
    ) -> [Question]
    /// 조건에 맞는 문제 수 (S3의 문제 수 활성화 판단용)
    func availableCount(category: QuizCategory?, difficulty: Difficulty, tags: Set<String>, questions: [Question]) -> Int
}

/// 세션 생성·진행·종료. SwiftData 저장을 담당
protocol SessionManaging {
    func startSession(category: QuizCategory?, difficulty: Difficulty, tags: Set<String>, count: Int) throws -> QuizSession   // category nil = 오늘의 출제
    /// `questionIndex`번째 문제(0부터)에 답을 저장한다. 문제는 순서대로만 제출할 수 있다.
    /// 이미 답이 있는 문제에 다시 호출하면 처음 저장된 답을 돌려주고 새로 저장하지 않는다(값이 달라도 유지).
    /// 아직 답하지 않은 앞선 문제가 있는 순서로 호출하면 오류를 던진다.
    /// 답 저장과 `currentIndex` 갱신(`answers.count`와 같은 값)은 한 번의 저장으로 처리한다
    func submit(answerIndex: Int, forQuestionAt questionIndex: Int, in session: QuizSession) throws -> SessionAnswer
    /// 이미 `completed`인 세션에 다시 호출하면 저장된 결과를 돌려주고 장식을 다시 지급하지 않는다.
    /// 세션 완료, 장식 지급, 트리 갱신은 한 번의 저장으로 처리한다. 실패하면 전부 취소하고 세션은 `inProgress`로 남아 재시도할 수 있다
    func finish(_ session: QuizSession) throws -> SessionResult
    func resumableSession() -> QuizSession?
    func abandon(_ session: QuizSession) throws
}

/// 세션 결과 요약
struct SessionResult {
    let correctCount: Int
    let totalCount: Int
    let accuracyPercent: Int
    let elapsed: TimeInterval
    let earnedDecorations: Int         // 기준 미만이면 0, 아니면 난이도별 지급 수 (이월분 포함)
    let treeCompleted: Bool            // 이번 세션으로 트리가 완성되었는가
    let carriedOver: Int               // 새 트리로 이월된 장식 수
    let wrongAnswers: [SessionAnswer]
}

/// 장식 지급과 트리 완성 처리
protocol TreeManaging {
    func currentTree() -> TreeRecord
    /// 장식을 지급한다. 12칸이 차면 완성 처리 후 새 트리를 시작하고, 남은 장식은 새 트리로 이월한다.
    /// 같은 ModelContext에서 값만 바꾸고, 저장(save)은 `SessionManaging.finish`가 한 번만 호출한다
    func grant(decorations: Int) throws -> TreeGrantResult
    func completedTrees() -> [TreeRecord]
}

/// 효과음과 햅틱
protocol FeedbackPlaying {
    func playCorrect()
    func playWrong()
    func playTreeComplete()
}

/// 장식 지급 결과
struct TreeGrantResult {
    let completedTree: TreeRecord?     // 이번 지급으로 완성된 트리 (없으면 nil)
    let carriedOver: Int               // 새 트리로 이월된 장식 수
    let currentDecorationCount: Int    // 지급 후 현재 트리의 장식 수
}

/// 애니메이션 문제 한 단계
struct TraceStep {
    let line: Int                       // 하이라이트할 코드 줄 (1부터)
    let narration: String               // 말풍선과 VoiceOver 설명
    let variables: [String: String]     // 이 단계 이후의 변수 값
    let sceneAction: TraceSceneAction   // 캐릭터와 배경의 동작
}

/// 캐릭터와 배경의 동작. 작업 5(애니메이션 문제)가 값을 정의한다.
/// 작업 0에서는 다른 작업이 컴파일되도록 빈 자리(`.none`)만 둔다
enum TraceSceneAction { case none }

/// animationID로 장면과 실행 순서를 찾는 저장소
protocol TraceSceneRegistry {
    func scene(for animationID: String) -> (steps: [TraceStep], view: AnyView)?
}
```

- 조회 결과가 없을 수 있는 값(`resumableSession`, `scene`)은 옵셔널로 반환하고 호출하는 쪽에서 안전하게 처리합니다.
- 설정값은 서비스가 직접 `@AppStorage`를 읽지 않고, 호출하는 쪽에서 값을 넘기거나 `SettingsStore`(UserDefaults 래퍼)를 주입합니다. **[가정]** 테스트하기 쉽게 하기 위해서입니다.

## 11. 공통 규칙

### 11-1. 코드
- 강제 언래핑(`!`)과 `try!`는 쓰지 않습니다. 옵셔널은 `guard let`, `if let`, `??`로 처리합니다.
- 공개 타입과 함수에는 문서화 주석(`///`)을 답니다. 이것이 API 문서 요구사항입니다.
- 색상은 Asset 카탈로그의 라이트/다크 색상 세트로만 정의합니다. 화면 코드에서 색상 값을 직접 쓰지 않습니다.
- 문자열은 한국어로 통일합니다.
- 뷰는 작게 나누고, 데이터 처리 로직은 Services에 둡니다. 뷰 안에서 SwiftData 조회를 직접 쓰는 경우는 `@Query`로 제한합니다.

### 11-2. 접근성
- 모든 텍스트는 Dynamic Type을 따르고, 가장 큰 글자 크기에서도 레이아웃이 망가지지 않아야 합니다(고정 높이 금지, 필요하면 스크롤).
- 중요한 이미지와 버튼에는 VoiceOver 라벨을 붙입니다.
- 모션 줄이기(`accessibilityReduceMotion`)가 켜져 있으면 이동·확대 연출을 페이드로 바꿉니다.
- 정답/오답은 색 외에 아이콘과 문구로 구분합니다.

### 11-3. 빈 상태
- 문제가 없는 경우(S10), 필터 결과가 0개인 경우, 오답이 없는 경우에는 안내 문구와 다음 행동 버튼을 보여 줍니다.

### 11-4. Git
- 브랜치: `main`(최종), `develop`(통합), `feature/*`(기능), `docs/*`(문서). feature와 docs는 develop에서 분기해 develop으로 병합합니다.
- 브랜치 이름: 기능은 `feature/<영역>-<내용>` (예: `feature/quiz-result-screen`), 문서만 바꾸는 작업은 `docs/<내용>` (예: `docs/project-spec`)
- `develop`과 `main`에는 직접 커밋하지 않고 PR로만 병합합니다.
- 커밋: Conventional Commits. `<type>(<scope>): <subject>`
  - 제목은 영어, 본문은 한글 목록(`-`)으로 작성합니다.
  - 커밋에 AI 관련 문구를 넣지 않습니다.
- PR은 최소 1명의 리뷰를 받고 병합합니다. 팀 규칙에 따라 AI가 짠 코드도 작성자가 설명할 수 있어야 합니다.
- 모델(`Models/`)을 바꾸는 PR은 팀원 모두에게 알립니다.

## 13. 비기능 요구사항

- **크래시 방지:** 11-1의 규칙을 지킵니다. 빈 배열 접근, 범위 밖 인덱스를 조심합니다. `choices.count != 4`인 문제는 편집 단계에서 저장할 수 없게 하고, 시드 로드 단계에서 건너뛰며 로그를 남깁니다.
- **성능:** 목록은 `List`나 `LazyVStack`을 씁니다. 큰 영상은 미리 로드하지 않고 해당 문제 화면에서만 로드합니다.
- **오프라인:** 네트워크 없이 모든 기능이 동작해야 합니다. 학습 자료 링크는 Safari로 여는 외부 링크이며, 오프라인이면 열리지 않습니다.
- **테스트:** 순수 로직(`TaskRecommender`, `QuestionSelector`, 보상 계산, 트리 완성)은 단위 테스트를 만듭니다.

## 16. 확인이 필요한 가정

팀 확인이 끝난 항목은 본문에서 `[가정]` 표시를 지웠습니다. 아직 확인하지 않은 항목은 아래 3개이고, 모두 영향이 작습니다.

1. **선호 카테고리의 정의:** 오늘의 출제의 30% 범주인 "선호 카테고리 문제"는 사용자가 자주 푼 카테고리의 문제로 봅니다(7-3).
2. **문제 작성 가이드 문서:** 시드 문제의 형식을 통일하기 위해 `docs/question-guide.md`를 만들어 해설 길이, 보기 개수, 태그 규칙을 정합니다(8-1).
3. **설정값 주입:** 서비스가 `@AppStorage`를 직접 읽지 않고 `SettingsStore`(UserDefaults 래퍼)를 주입받아 테스트하기 쉽게 만듭니다(9장).
