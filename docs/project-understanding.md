## 1. 한 줄 요약

**"산타의 작업실 탈출"** 은 iOS 개발 학습용 퀴즈 앱입니다. SwiftUI와 SwiftData로 만들고, 아이폰 세로 화면과 iPad를 지원합니다.
한 세션의 문제를 모두 풀면 정답률 80%(설정에서 사용자 변경 가능) 이상일 시 크리스마스 트리 장식이 하나씩 채워지고, 트리를 완성하면 산타가 루돌프를 타고 선물을 주러 떠납니다. 학습을 게임처럼 오래 이어가게 하는 것이 목표입니다.

## 2. 과제 필수 요건 (원래 요구사항)

- 퀴즈 CRUD(만들기·보기·고치기·지우기). 문제에는 텍스트, 이미지, 영상을 넣을 수 있음
- 반응형 출제: 정답률과 카테고리 선호도를 분석해 문제를 자동 선택
- 세션(한 판) 종료 시 점수, 오답 노트, 추천 학습 자료 요약
- 카테고리·태그·난이도 필터, 주·월별 성과 대시보드
- 저장
  - SwiftData: 퀴즈, 세션 기록, 통계
  - @AppStorage(UserDefaults, 간단한 설정값 저장소): 테마, 글꼴 크기, 첫 실행 여부
- UI
  - SwiftUI 기본 컴포넌트 우선 사용 (NavigationStack, List, Form 등)
  - 정답·오답 피드백(색, 진동, 사운드)
  - 다크모드 대응
  - iPhone 세로 기본, iPad는 선택, macOS 제외
- 접근성: Dynamic Type(사용자가 정한 글자 크기에 맞춰 화면이 바뀌는 기능) 대응, 한국어 또는 영어 중 한 언어로 통일
- 크래시 방지: 옵셔널(값이 없을 수도 있는 변수)을 안전하게 처리
- 문서: README(기능, 설치, 라이브러리, 폴더 구조), 스크린샷·GIF(작성-조회-통계 흐름), 문서화 주석(API 문서)

### 게임 규칙 (와이어프레임 기준)
- 한 세션 = 문제 10개
- 정답 1개당 트리 장식 1개. 오답은 그 문제의 장식만 못 얻고, 기존 보상은 줄지 않음(벌칙 없음)
- 트리 장식 12칸을 채우면 열쇠 조각 1개, 열쇠 조각 3개를 모으면 문이 열려 다음 방으로 이동
- 방 = 카테고리: 서재(iOS), 아틀리에(Design), 연구실(CS). 새 방은 이전 방을 열어야 해금
- 연속 정답, 일일 미션 달성 시 선물 상자 → 열면 특별 장식

### 공통 규칙
- 정답: 햅틱 success + 짧은 효과음 + 장식이 트리로 날아가는 애니메이션
- 오답: 햅틱 error + 보기 좌우 흔들림
- 색만으로 구분하지 않고 ✓/✕ 아이콘과 문구를 함께 표시
- 모션 줄이기 설정 시 날아가는 연출을 페이드로 대체
- 방 일러스트는 낮/밤 두 벌, 이미지·영상 문제는 다크모드에서도 원본 유지
- 빈 상태(문제 없음, 필터 결과 0개, 오답 없음)에는 안내 문구와 다음 행동 버튼 표시
- VoiceOver 라벨 제공

## 5. 확인이 필요한 질문

### A. 문서끼리 맞지 않거나 불분명한 부분

**A-1. 보상 방식**
기획서는 "난이도별 보상 차등(쉬움 1개, 보통 2개, 어려움 3개)", 와이어프레임은 "정답 1개당 장식 1개"입니다. 어느 쪽이 맞나요? 합치는 안(정답 1개당 장식 수에 난이도 배율 적용)도 가능합니다.
- 답변: 난이도별 보상 차등이 맞아. 와이어프레임에서 게임 방식이 수정되었어. 이제 한판(하나의 세션)이 끝나면 그 결과를 기준으로 보상인 장식을 지급할거야.

**A-2. 세션 문제 수**
기획서는 "풀 문제 개수 선택", 와이어프레임은 "10문제 고정"입니다.
- 답변: 풀 문제 수를 선택할 수 있으면 좋겠어. 5, 10, 15개 이렇게

**A-3. 트리 규모**
장식 12칸 = 열쇠 1개, 열쇠 3개 = 방 해금이면, 방 하나를 열려면 트리를 3번 완성해야 합니다(세션 최소 12번). 의도한 게 맞나요?
- 답변: 열쇠라는 개념을 지우고 장식이 모두 모이면 방을 떠나 산타가 선물 배달을 시작하도록 만들거야. 대신 열쇠가 없어지는 만큼 장식은 문제당 1개가 아니라 세션당 난이도에 따라 다르게 지급할거야. 설정에서는 세션에서 몇퍼센트 이상 정답일 때 장식을 획득할 수 있는지 사용자가 설정할 수 있도록 하면 좋겠어. 기본은 80% 이상 정답이면 보상을 주도록 하자

**A-4. "작업 선택(소원 접수, 선물 생산, 포장, 썰매 적재)"**
기획서 끝에 단어만 적혀 있습니다. 방(서재/아틀리에/연구실)과의 관계가 무엇인가요? (카테고리 이름 / 난이도 이름 / 세션 입장 단계 / 기타)
- 답변: 방탈출의 요소를 가미했지만 우리의 테마인 산타클로스에 맞춰 방 이름을 작업으로 대체하고 싶어, 지금 우리 퀴즈의 카테고리가 swift 문법, hig, ai 활용, kxcoding이자나 이거에 맞춰서 4개로 나눠서 작업을 만들어뒀어

**A-5. 난이도 선택지**
참고 예시 화면에는 "섞기"가 있고, 우리 용어는 쉬움/보통/어려움 3개입니다. "섞기"를 넣을까요?
- 답변: 일단 섞기는 빼고 진행할게

### C. 범위와 역할

**C-1. 1차 범위의 문제 형식**
"추가 구현"으로 적힌 것은 주관식·서술형, 트리 장식 눌러 입장입니다. 선긋기와 복수 선택은 1차에 포함할까요? (형식이 5개라 개발량 차이가 큽니다)
- 답변: 빼고 객관식 하나 선택만 하자

**C-2. 문제 데이터 출처**
앱 내부 저장소 / 외부 API(Wikipedia 등) 중 무엇인가요? 앱에 JSON 시드(초기 문제 데이터)를 넣고 시작한다면, 문제 수와 작성 담당자도 정해야 합니다.
- 답변: 내부 저장소로만 만들거야. 퀴즈도 미리 앱에 심어둘 생각이야

**C-3. 언어**
앱 UI와 문제는 한국어로 통일하는 게 맞나요?
- 답변: 한국어로 통일해줘

**C-4. 기본 테마**
시안은 다크 화면이고, 참고 예시는 라이트입니다. 기본 다크 고정인지, 시스템 설정을 따르는지(요구사항은 시스템 따름)?
- 답변: 시스템 설정에 따라 변경할거야. 색상의 asset에서 라이트/다크 모드 모두 대응하도록 만들거야.

**C-5. 팀 구성과 일정**
인원수, 각자 맡고 싶은 영역, 마감일을 알려 주세요. (역할 분담 섹션에 사용)
- 답변: 역할 분담은 우리가 알아서 정리할게 이건 따로 정리할 필요는 없고, 작업만 어떻게 나눠서 하면 좋을지 분리해줘

**C-6. iPad**
이번에는 제외하고 iPhone 세로만 할까요?
- 답변: iPad도 포함해서 진행할게

**C-7. 개발 환경**
Xcode 버전, 최소 iOS 버전. SwiftData는 iOS 17 이상이 필요합니다.
- 답변: iOS 17 버전부터 지원할거야

### 7-3. 애니메이션 문제 (신규)

rabbit-quiz-v3.html은 아래 구조로 동작합니다.
1. 코드를 보여 주고 보기(2~3개)를 고르게 합니다.
2. 보기를 고르면 코드가 한 줄씩 하이라이트되면서 캐릭터(토끼)가 그 줄을 실행하는 모습을 보여 줍니다. 말풍선으로 조건 결과(예: `3 > 3 → false`)와 변수 값 변화도 표시합니다.
3. 끝나면 정답 여부와 해설을 보여 줍니다.
4. 코드 토큰(예: `guard`, `??`)에 마우스를 올리면 짧은 설명이 뜹니다.
5. 효과음은 파일이 아니라 코드로 소리를 합성합니다(Web Audio).
6. 문제 하나는 "코드 + 장면(캐릭터와 배경) + 실행 순서"로 정의됩니다.

우리 앱에서는 토끼 대신 산타 테마 캐릭터와 장면으로 바꿔서 구현한다고 이해했습니다. 이를 바탕으로 한 질문입니다.

**Q4. 개발 범위를 어디까지 할지**
