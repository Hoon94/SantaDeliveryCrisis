# 작업 2. 세션 로직

- 상위 문서: [프로젝트 스펙](../../.kiro/steering/project-spec.md). 이 문서에서 말하는 5장, 8장, 9장, 11장은 그 문서의 장입니다. 데이터 모델(8장)과 모듈 인터페이스(9장)는 모든 작업이 맞춰야 하는 공통 계약이라 그쪽에 있습니다.
- 통합 완료 조건과 확인 담당: [통합 계약표](../integration-contracts.md)
- 표기: `[가정]`은 팀이 아직 확정하지 않은 내용입니다. 구현 전에 사용자에게 확인합니다(프로젝트 스펙 16장).

## 작업 범위

- 포함: `QuestionSelector`, `SessionManager`, 보상 계산, `TreeManager`, 단위 테스트
- 의존: 0
- 병렬 가능: 1, 3, 4와 병렬

## 반응형 출제

세션은 두 가지 방식으로 시작합니다.

| 방식 | 시작 위치 | 카테고리 | 사용자가 고르는 것 |
| --- | --- | --- | --- |
| 오늘의 출제 | S1 "문제 풀기" → S3a | 4개 작업을 섞어서 앱이 구성 | 난이도, 문제 수 |
| 선택 출제 | S2(출제 탭)에서 켜진 장식을 누름 | 누른 장식의 카테고리 하나 | (S3b에서) 난이도, 카테고리, 태그(선택), 문제 수 |

작업 추천 배지와 점수식(`TaskRecommender`)은 1차에서 뺐습니다([future-work.md](../future-work.md)). 선택 출제는 사용자가 카테고리를 직접 고르므로 추천이 필요하지 않습니다.

**문제 선택 (`QuestionSelector`)**
선택한 난이도의 문제 중에서 다음 비율로 고릅니다. 후보 범위는 오늘의 출제는 4개 작업 전체, 선택 출제는 누른 장식의 카테고리와 태그(고른 경우)입니다. 태그를 고르지 않으면 전체 태그가 대상이고, 여러 개를 고르면 그중 하나라도 가진 문제가 대상입니다. 아래 비율은 이 후보 안에서 같은 방식으로 적용합니다.

**오늘의 출제 (3개 범주)**

| 비율 | 범주 |
| --- | --- |
| 50% | 약한 문제: 최근 오답이거나 정답률이 낮은 문제 |
| 30% | 선호 카테고리 문제: 사용자가 자주 푼 카테고리의 문제 |
| 20% | 오래 안 푼 문제 또는 한 번도 안 푼 문제 |

- 범주별 문제 수는 비율대로 계산해 내림하고, 남는 자리는 약한 문제 범주부터 채웁니다. 5문제는 3·1·1, 10문제는 5·3·2, 15문제는 8·4·3입니다.

**선택 출제 (2개 범주) `[가정]`**
후보가 모두 같은 카테고리라서 선호 범주를 두지 않습니다.

| 비율 | 범주 |
| --- | --- |
| 50% | 약한 문제 |
| 50% | 오래 안 푼 문제 또는 한 번도 안 푼 문제 |

- 내림하고 남는 자리는 약한 문제 범주부터 채웁니다. 5문제는 3·2, 10문제는 5·5, 15문제는 8·7입니다.

**공통 규칙**
- 한 문제가 여러 범주에 해당하면 약한 문제 → 선호 카테고리(오늘의 출제만) → 오래 안 푼 문제 순서로 먼저 배정하고, 한 번 뽑힌 문제는 다른 범주 후보에서 뺍니다. 중복 출제는 없습니다.
- 한 범주에서 후보가 모자라면 나머지 범주에서 같은 순서로 채웁니다.
- 모든 범주를 쓰고도 문제 수가 모자라면 같은 필터 안의 남은 후보에서 중복 없이 무작위로 채웁니다. 필터 전체의 후보 자체가 모자라면 `startSession`이 오류를 던집니다(S3는 `availableCount`로 미리 막습니다).
- "정답률이 낮은 문제"와 "오래 안 푼 문제"의 기준값, 범주 안에서의 선택과 동률 처리는 작업 2 담당자가 정하고 문서화 주석에 적습니다.
- 기록이 없는 새 사용자는 모든 문제를 "한 번도 안 푼 문제"로 보고 무작위로 고릅니다.
- 정해진 문제 수에서 순서는 무작위로 섞습니다.

## 이어서 풀기
- 문제 하나에 답하고 [확인]을 누를 때마다 세션 상태를 SwiftData에 저장합니다.
- 앱을 시작할 때 `inProgress` 상태 세션이 있으면 S1에 "이어서 풀기"를 보여 줍니다.
- 복원 위치는 저장된 답의 수(`answers.count`)번째 문제입니다. `currentIndex`는 답을 저장하는 같은 저장에서 `answers.count`와 같은 값으로 갱신하고, 둘이 다르면 `answers.count`를 따릅니다. 이미 답이 저장된 문제는 다시 채점하지 않습니다.
- 모든 문제의 답이 저장된 상태에서 종료됐다면, 복원할 때 문제 화면 없이 결과 계산(`finish`)부터 진행합니다.
- 피드백이나 애니메이션을 보던 도중에 종료됐다면, 다시 재생하지 않고 다음 문제로 이동합니다. 놓친 해설은 결과 화면의 오답 노트에서 볼 수 있습니다.
- 소요 시간(`elapsedSeconds`)은 퀴즈 화면이 떠 있고 앱이 활성 상태인 동안만 누적합니다. 답을 저장할 때와 앱이 백그라운드로 갈 때 저장하고, 이어 풀 때는 저장된 값에서 이어서 더합니다. 마지막 문제의 피드백·애니메이션을 보는 시간도 포함하며, `finish`가 마지막 누적값을 저장한 뒤 확정합니다. 앱이 강제 종료되면 마지막 저장 이후의 시간은 빠질 수 있습니다.
- 진행 중 세션이 있는데 사용자가 새 세션을 시작하려고 하면 "이어서 풀기"와 "새로 시작(기존 세션 버림)" 중 고르게 하고, 새로 시작을 고르면 확인 대화상자를 한 번 보여 준 뒤 기존 세션을 `abandoned`로 바꿉니다.
